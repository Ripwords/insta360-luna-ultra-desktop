# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a statically-generated, SEO-oriented documentation site at `https://ripwords.github.io/luna-ultra-desktop/`, built as a second Nuxt app that consumes the desktop app as a Nuxt layer without moving any of its files.

**Architecture:** `docs/site/` is a Nuxt 4 app declaring `extends: ["../.."]`, so the desktop app's components, composables and utils are available to it. It overrides the app's `ssr: false` with `ssr: true` so prose prerenders as static HTML. The app's own routes arrive with the layer and are re-prefixed to `/demo/*` by a `pages:extend` hook so they cannot collide with docs routes. Content is Markdown via `@nuxt/content` v3, rendered with Nuxt UI's content components; SEO comes from `@nuxtjs/seo`.

**Tech Stack:** Nuxt 4.5, Nuxt UI 4.10, `@nuxt/content` ^3, `@nuxtjs/seo`, Bun workspaces, GitHub Actions + Pages.

## Global Constraints

- Package manager is **Bun**. Never run `npm` or `yarn`.
- Conventional Commits (`feat:`, `fix:`, `chore:`, `refactor:`, `test:`, `docs:`, `ci:`).
- **Never use `any`.** `as unknown as X` only when strictly necessary. `as never` is banned.
- `oxlint --deny-warnings` — warnings are failures. The pre-commit hook runs `oxfmt` + `oxlint --fix` on staged files. Never `git commit --no-verify`.
- Vue conventions, **not lint-enforced, apply by hand**: prop shorthand (`:foo`, not `:foo="foo"`); `useTemplateRef()` rather than a manually typed ref bound to `ref="..."`; destructuring defaults on `defineProps`, never `withDefaults()`.
- **The desktop app must keep working.** `bun run test`, `bun run typecheck`, `bun run lint` and `bun run dev` must all behave exactly as before, at every task boundary.
- Site URL is exactly `https://ripwords.github.io/luna-ultra-desktop` and base path is exactly `/luna-ultra-desktop/`.
- The camera seam is enforced by an oxlint `no-restricted-imports` rule: nothing may import `~/utils/lunaClient` except `app/utils/transport.ts` and `tests/transport.test.ts`. The docs site talks to the camera only through `CameraTransport`.

**Interfaces:**

- [ ] **Step 1: Add the route-prefixing hook**

In `docs/site/nuxt.config.ts`, add a `hooks` block. Layer-sourced pages are identified by their file path — they live outside this app's own `app/pages` directory:

```ts
  hooks: {
    "pages:extend"(pages) {
      // Routes inherited from the desktop-app layer live under /demo/* so they
      // cannot collide with docs routes. Identified by file path: the layer's
      // pages resolve to the repo root's app/pages, not this app's.
      const isFromLayer = (file?: string) =>
        !!file && file.includes("/app/pages/") && !file.includes("/docs/site/");

      for (const page of pages) {
        if (!isFromLayer(page.file)) continue;
        page.path = page.path === "/" ? "/demo" : `/demo${page.path}`;
        page.name = page.name ? `demo-${page.name}` : undefined;
        page.meta = { ...page.meta, layout: "demo" };
      }
    },
  },
```

`layout: "demo"` is set now so the routes never fall through to the docs layout. The follow-up demo plan creates `layouts/demo.vue`; until then Nuxt resolves an unknown layout to no layout, which renders the page bare. That is expected at this stage.

````md
## macOS

::callout{icon="i-lucide-triangle-alert"}
"'Luna Ultra Desktop' is damaged and can't be opened"
::

The app is signed ad-hoc but not notarized, so Gatekeeper quarantines it on
download. It is not actually damaged. Drag it to **Applications**, then clear the
quarantine attribute:

```bash
xattr -cr "/Applications/Luna Ultra Desktop.app"
```

Then open it normally, or right-click → Open the first time. If the app lives
elsewhere, point the command at that path instead.

`xattr -cr` clears all extended attributes recursively. To remove only the
quarantine flag:

```bash
xattr -dr com.apple.quarantine "/Applications/Luna Ultra Desktop.app"
```

### Local network permission

Reaching the camera at `192.168.42.1` requires macOS's Local Network permission.
Allow it when prompted, or enable it under
**System Settings › Privacy & Security › Local Network**.

The permanent fix for both warnings is Apple Developer ID signing plus
notarization, which needs a paid account. Once that is set up, this step goes
away.

## Windows

::callout{icon="i-lucide-triangle-alert"}
"Windows protected your PC" (SmartScreen)
::

The build is unsigned, so SmartScreen warns on first launch: click
**More info → Run anyway**. The MSI installer also shows a standard UAC prompt.

No firewall permission is needed — Windows allows the outbound connection to the
camera automatically.

## Linux

The AppImage needs to be made executable before it will run:

```bash
chmod +x "Luna Ultra Desktop_0.1.0_amd64.AppImage"
./"Luna Ultra Desktop_0.1.0_amd64.AppImage"
```

Some distributions need FUSE. On Ubuntu 22.04 and later:

```bash
sudo apt install libfuse2
```

`.deb` and `.rpm` packages install with your package manager
(`sudo apt install ./*.deb` or `sudo dnf install ./*.rpm`), and need no
local-network permission.

::callout{icon="i-lucide-info"}
Auto-updates apply to the **AppImage** build only. `.deb` and `.rpm` installs
must be updated manually.
::
````

- [ ] **Step 4: Write the connecting page**

Create `docs/site/content/docs/2.connecting.md`. Source: the README's `## How it connects` section (line 139), plus the connection behaviour that is only visible in the code.

```md

title: Connecting to the camera
description: Join the Luna Ultra's Wi-Fi network, connect from the app, and troubleshoot a failed session.
```

Cover, in this order:

1. **Join the camera's Wi-Fi.** The camera exposes its own network; the app talks to the gateway at `192.168.42.1`, which is the default host the Connect screen pre-fills.
2. **Connect.** What the Connect screen does and that the host is remembered between launches (it is persisted to `localStorage` under `luna-camera-host`, per `app/composables/useCamera.ts`).
3. **What is actually happening** — port the README's two bullet points describing TCP control on port 6666 (UCD2-framed, used for auth, device info and delete) and HTTP on port 80 (file index and `Range`-capable downloads), and that a live control session is what authorises the HTTP index.
4. **Auto-reconnect.** The app retries on a backoff schedule of 1s, 2s, 5s, 10s, 15s (the last repeating) and retries immediately when the OS reports the network came back. Verify these values against `RETRY_DELAYS_MS` in `app/composables/useCamera.ts` before publishing them.
5. **Troubleshooting.** Camera control requires the desktop app — a browser cannot open a raw TCP socket, so the web build shows a message saying so. If the gallery says "Nothing here" while connected, the HTTP media index returned a non-ok response; that is a media-index problem, not a live-view one.

```js
import { dirname, resolve } from "node:path";

const here = dirname(fileURLToPath(import.meta.url));
```

### Task 4: SEO

**Files:**

- Modify: `docs/site/nuxt.config.ts`
- Create: `docs/site/app/components/JsonLd.vue` (only if Step 3 shows it is needed — see that step)
- Modify: `docs/site/app/pages/index.vue`

**Interfaces:**

- Consumes: pages with `title`/`description` from Tasks 2 and 3.
- Produces: `sitemap.xml`, `robots.txt`, canonical URLs, OG images and a `SoftwareApplication` JSON-LD block. Task 5 deploys them.

`@nuxtjs/seo` is already registered in `modules` from Task 1. This task configures it and verifies the output — configuration that is never checked is the most common way SEO work silently does nothing.

- [ ] **Step 1: Exclude the demo routes from indexing**

The `/demo/*` routes are client-rendered app chrome; indexing them fills search results with UI strings instead of prose. Add to `docs/site/nuxt.config.ts`:

```ts
  robots: {
    disallow: ["/demo"],
  },

  sitemap: {
    exclude: ["/demo/**"],
  },
```

- [ ] **Step 2: Set a default social preview image**

`nuxt-og-image` (bundled by `@nuxtjs/seo`) renders share images with **satori**, so no headless browser is needed at build time. Give every page a default rather than leaving link previews blank. Add to `docs/site/nuxt.config.ts`:

```ts
  ogImage: {
    defaults: {
      component: "NuxtSeo",
      props: {
        title: "Luna Ultra Desktop",
        description: "A desktop companion for the Insta360 Luna Ultra.",
      },
    },
  },
```

`NuxtSeo` is the module's built-in template component — no custom component needed for a default. Individual pages can override later with `defineOgImageComponent()`; that is not required now.

Satori renders text, so it needs a font it can embed. If the build errors about a missing font, the module's default is Inter fetched at build time — in that case pin an explicit font in `ogImage.fonts` rather than disabling the feature, and note what you did in your report.

- [ ] **Step 3: Describe the app with structured data**

Add a `SoftwareApplication` JSON-LD block to the landing page — this is what earns rich results for a downloadable app. In `docs/site/app/pages/index.vue`, inside `<script setup>`, after the existing `useSeoMeta` call:

```ts
useSchemaOrg([
  defineSoftwareApp({
    name: "Luna Ultra Desktop",
    applicationCategory: "MultimediaApplication",
    operatingSystem: "macOS, Windows, Linux",
    offers: { "@type": "Offer", price: "0", priceCurrency: "USD" },
    url: "https://ripwords.github.io/luna-ultra-desktop",
  }),
]);
```

`useSchemaOrg` and `defineSoftwareApp` are auto-imported by `nuxt-schema-org`, which `@nuxtjs/seo` bundles. If either fails to resolve, check the module actually loaded before hand-rolling a `<script type="application/ld+json">` — and if you do end up hand-rolling it, that is when `JsonLd.vue` gets created.

```bash

```

### Task 5: Deploy to GitHub Pages

**Files:**

- Create: `.github/workflows/docs.yml`

**Interfaces:**

- Consumes: `bun run docs:generate` from Task 1.
- Produces: a live site. Nothing depends on this task.

- [ ] **Step 1: Write the workflow**

Create `.github/workflows/docs.yml`. Note this repo's existing workflows use `oven-sh/setup-bun@v2` and `actions/checkout@v4` — match that:

```yaml
name: Docs

on:
  push:
    branches: [master]
    paths:
      - "app/**"
      - "docs/**"
      - "package.json"
      - "bun.lock"
      - "nuxt.config.ts"
      - ".github/workflows/docs.yml"
  workflow_dispatch:

# Allow one concurrent deployment, and let a newer push cancel an in-flight one.
concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-22.04
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: latest
      - run: bun install --frozen-lockfile
      - name: Build the docs site
        run: bun --cwd docs/site run generate
        env:
          NUXT_APP_BASE_URL: /luna-ultra-desktop/
      - uses: actions/upload-pages-artifact@v3
        with:
          path: docs/site/.output/public

  deploy:
    needs: build
    runs-on: ubuntu-22.04
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

`NUXT_APP_BASE_URL` is set as well as `app.baseURL` in the config; they agree, and the env var is what Nuxt's own GitHub Pages guidance uses. The `github_pages` Nitro preset (which writes `.nojekyll`) is applied automatically by Nitro when it detects GitHub Actions — verify `.nojekyll` exists in the artifact in Step 3, and if it does not, add `nitro: { preset: "github_pages" }` to the docs site config.

- [ ] **Step 2: Ask the repo owner to enable Pages**

This cannot be done from code. Report to your human partner:

> GitHub Pages needs its source set to **GitHub Actions** at
> `https://github.com/Ripwords/luna-ultra-desktop/settings/pages`.
> The workflow will fail at the deploy step until that is done.

- [ ] **Step 3: Verify the artifact locally before pushing**

```bash
NUXT_APP_BASE_URL=/luna-ultra-desktop/ bun --cwd docs/site run generate
ls -a docs/site/.output/public | head -20
```

Confirm `.nojekyll` is present (without it, GitHub Pages silently drops any `_`-prefixed directory, which breaks Nuxt's `_nuxt/` asset folder and yields an unstyled site). If it is absent, add the Nitro preset as described in Step 1 and regenerate.

Then preview the built site and click through every page:

```bash

```

```bash

```
